# OpenAPI Support

Ultimo automatically generates OpenAPI 3.0 specifications from your RPC procedures, enabling integration with Swagger UI, Postman, and code generation tools.

## Overview

The OpenAPI generator creates complete API specifications including:

- All RPC endpoints with paths and methods
- Request/response schemas from TypeScript type definitions
- Parameter definitions (path, query, body)
- HTTP status codes and error responses
- Server information and metadata

## Basic Usage

Generate an OpenAPI spec from your RPC registry:

```rust
use ultimo::prelude::*;
use ultimo::rpc::RpcMode;

let rpc = RpcRegistry::new_with_mode(RpcMode::Rest);

// Register procedures
rpc.query("getUser", handler, "{ id: number }", "User");
rpc.mutation("createUser", handler, "{ name: string; email: string }", "User");

// Generate OpenAPI spec
let openapi = rpc.generate_openapi(
    "My API",        // API title
    "1.0.0",         // Version
    "/api"           // Base path
);

// Write to file
openapi.write_to_file("openapi.json")?;
```

## Complete Example

```rust
use ultimo::prelude::*;
use ultimo::rpc::RpcMode;
use serde::{Deserialize, Serialize};

#[derive(Deserialize)]
struct GetUserInput {
    id: u32,
}

#[derive(Serialize)]
struct User {
    id: u32,
    name: String,
    email: String,
    created_at: String,
}

#[derive(Deserialize)]
struct CreateUserInput {
    name: String,
    email: String,
}

#[derive(Deserialize)]
struct ListUsersInput {
    page: Option<u32>,
    limit: Option<u32>,
}

#[tokio::main]
async fn main() -> Result<()> {
    let mut app = Ultimo::new();
    let rpc = RpcRegistry::new_with_mode(RpcMode::Rest);

    // Register queries (GET)
    rpc.query(
        "listUsers",
        |input: ListUsersInput| async move {
            Ok(json!({
                "users": [],
                "total": 0,
                "page": input.page.unwrap_or(1)
            }))
        },
        r#"{
          page?: number;
          limit?: number;
        }"#.to_string(),
        r#"{
          users: User[];
          total: number;
          page: number;
        }"#.to_string(),
    );

    rpc.query(
        "getUser",
        |input: GetUserInput| async move {
            Ok(User {
                id: input.id,
                name: "Alice".to_string(),
                email: "alice@example.com".to_string(),
                created_at: "2024-01-01T00:00:00Z".to_string(),
            })
        },
        "{ id: number }".to_string(),
        r#"{
          id: number;
          name: string;
          email: string;
          created_at: string;
        }"#.to_string(),
    );

    // Register mutations (POST)
    rpc.mutation(
        "createUser",
        |input: CreateUserInput| async move {
            Ok(User {
                id: 1,
                name: input.name,
                email: input.email,
                created_at: "2024-01-01T00:00:00Z".to_string(),
            })
        },
        r#"{
          name: string;
          email: string;
        }"#.to_string(),
        "User".to_string(),
    );

    rpc.mutation(
        "deleteUser",
        |input: GetUserInput| async move {
            Ok(json!({ "success": true }))
        },
        "{ id: number }".to_string(),
        "{ success: boolean }".to_string(),
    );

    // Generate OpenAPI specification
    let openapi = rpc.generate_openapi(
        "User Management API",
        "1.0.0",
        "/api"
    );

    openapi.write_to_file("openapi.json")?;
    println!("✅ OpenAPI spec generated: openapi.json");

    app.listen("127.0.0.1:3000").await
}
```

## Documenting REST routes

For routes you register yourself, describe each operation with the
constructors in `ultimo::openapi`:

```rust
use ultimo::openapi::{OpenApiBuilder, Operation, Parameter, PathItem, RequestBody, Response, Schema};

let mut spec = OpenApiBuilder::new().title("User API").version("1.0.0").build();

spec.add_schema("User", Schema::object([
    ("id", Schema::integer()),
    ("name", Schema::string()),
]));

spec.add_path(
    "/users/{id}",
    PathItem::new().get(
        Operation::new()
            .summary("Get user by ID")
            .tag("users")
            .parameter(Parameter::path("id", Schema::integer()))
            .response("200", Response::json("The user", Schema::reference("User")))
            .response("404", Response::new("Not found")),
    ),
);

spec.add_path(
    "/users",
    PathItem::new().post(
        Operation::new()
            .summary("Create a user")
            .request_body(RequestBody::json(Schema::reference("User")))
            .response("201", Response::json("Created", Schema::reference("User"))),
    ),
);

app.serve_docs("/docs", spec); // Swagger UI at /docs, the spec at /docs/openapi.json
```

The types are `#[non_exhaustive]`, so build them with these constructors
(`Operation::new()`, `Response::json(..)`, `Schema::object(..)`, …) rather than
struct literals. Every field stays public: set anything without a helper
directly, e.g. `op.description = Some("…".into())`.

## Authentication

Declare how clients authenticate and Swagger UI shows an **Authorize** button.
Once someone enters a token or key there, every "Try it out" request sends it.

```rust
use ultimo::openapi::{OpenApiBuilder, Operation, SecurityScheme};

let mut spec = OpenApiBuilder::new()
    .title("User API")
    .version("1.0.0")
    .security_scheme("bearerAuth", SecurityScheme::bearer_jwt())
    .security("bearerAuth") // required on every operation by default
    .build();

// Opt one operation out of the default:
let health = Operation::new().summary("Health check").public();

// Or require something else on one operation (alternatives are OR-ed):
let delete = Operation::new()
    .security("bearerAuth")
    .security_with_scopes("oauth", &["users:delete"]);
```

Pick the scheme that matches the auth middleware you use:

| You protect routes with | Declare |
| --- | --- |
| [`Jwt::hs256` / `Jwt::oidc`](/jwt) | `SecurityScheme::bearer_jwt()` |
| [`ApiKey`](/api-keys) | `SecurityScheme::api_key_header("X-API-Key")` (or `api_key_query` / `api_key_cookie`) |
| [`BasicAuth`](/middleware) | `SecurityScheme::basic()` |
| Tokens from an OpenID Connect provider | `SecurityScheme::open_id_connect(discovery_url)` |
| Tokens from an OAuth2 provider | `SecurityScheme::oauth2_authorization_code(auth_url, token_url, &[("scope", "description")])` or `oauth2_client_credentials(token_url, scopes)` |

`.description(..)` on any scheme adds text to the Authorize dialog.

The spec **documents** authentication; it doesn't enforce it. Your middleware
still does the checking, so keep the two in step: an operation marked
`.public()` should really be reachable without credentials.

**For a generated spec** — from `RpcRegistry::generate_openapi` — add security
after the fact:

```rust
let mut spec = rpc.generate_openapi("My API", "1.0.0", "/api");
spec.add_security_scheme("bearerAuth", SecurityScheme::bearer_jwt());
spec.require_security("bearerAuth");
if let Some(op) = spec.operation_mut("/api/health", "get") {
    op.security = Some(vec![]); // public
}
```

The [`openapi-demo`](https://github.com/ultimo-rs/ultimo/tree/main/examples/openapi-demo)
REST server protects its write endpoints with an API key and documents it this
way — run it and try the Authorize button.

## Upgrading from 0.9

0.10 made the OpenAPI types `#[non_exhaustive]` so that new OpenAPI fields can
be added later without breaking your code again. Code that built them with
struct literals needs to switch to the constructors:

```rust
// 0.9
let op = Operation {
    summary: Some("Get user".to_string()),
    description: None,
    operation_id: Some("getUser".to_string()),
    tags: Some(vec!["users".to_string()]),
    parameters: None,
    request_body: None,
    responses: HashMap::new(),
};
spec.add_path("/users/{id}".to_string(), PathItem { get: Some(op), post: None, put: None, delete: None, patch: None });

// 0.10
let op = Operation::new().summary("Get user").operation_id("getUser").tag("users");
spec.add_path("/users/{id}", PathItem::new().get(op));
```

| 0.9 literal | 0.10 |
| --- | --- |
| `Operation { .. }` | `Operation::new()` + `.summary()`, `.tag()`, `.parameter()`, `.request_body()`, `.response()` |
| `PathItem { .. }` | `PathItem::new().get(op).post(op)…` |
| `Parameter { .. }` | `Parameter::path(name, schema)`, `::query`, `::header`, `::new(name, location, schema)` |
| `RequestBody { .. }` | `RequestBody::json(schema)` |
| `Response { .. }` | `Response::new(description)`, `Response::json(description, schema)` |
| `MediaType { .. }` | `MediaType::new(schema).example(json)` |
| `Schema { .. }` | `Schema::string()`, `::integer()`, `::of_type(..)`, `::array(..)`, `::object([..])`, `::reference("User")` |
| `Server` / `Tag` / `Info` / `License` | `::new(..)`, or the `OpenApiBuilder` methods |

Reading fields, matching on them and mutating them works as before.
`add_path` and `add_schema` now take `impl Into<String>`, so `.to_string()`
on the path is no longer needed (it still compiles).

```bash
openapi-generator-cli generate \
  -i openapi.json \
  -g typescript-fetch \
  -o ./typescript-client

# Generate Python client
openapi-generator-cli generate \
  -i openapi.json \
  -g python \
  -o ./python-client

# Generate Go client
openapi-generator-cli generate \
  -i openapi.json \
  -g go \
  -o ./go-client
```

## Advanced Type Definitions

### Complex Types

```rust
rpc.query(
    "searchUsers",
    handler,
    r#"{
      query: string;
      filters?: {
        role?: 'admin' | 'user' | 'guest';
        active?: boolean;
        createdAfter?: string;
      };
      sort?: {
        field: 'name' | 'email' | 'created_at';
        order: 'asc' | 'desc';
      };
      pagination?: {
        page: number;
        limit: number;
      };
    }"#.to_string(),
    r#"{
      results: User[];
      total: number;
      page: number;
      hasMore: boolean;
    }"#.to_string(),
);
```

### Arrays and Objects

```rust
rpc.mutation(
    "bulkCreateUsers",
    handler,
    r#"{
      users: Array<{
        name: string;
        email: string;
      }>;
    }"#.to_string(),
    r#"{
      created: User[];
      failed: Array<{
        email: string;
        error: string;
      }>;
    }"#.to_string(),
);
```

### Union Types

```rust
rpc.query(
    "getResource",
    handler,
    "{ id: number }".to_string(),
    r#"{
      data: User | Post | Comment;
      type: 'user' | 'post' | 'comment';
    }"#.to_string(),
);
```

## RPC Mode Differences

### REST Mode

Each procedure gets its own path:

```json
{
  "paths": {
    "/getUser": {
      "get": { ... }
    },
    "/createUser": {
      "post": { ... }
    }
  }
}
```

### JSON-RPC Mode

Single endpoint with method parameter:

```json
{
  "paths": {
    "/rpc": {
      "post": {
        "requestBody": {
          "schema": {
            "properties": {
              "method": {
                "type": "string",
                "enum": ["getUser", "createUser", "deleteUser"]
              },
              "params": { ... }
            }
          }
        }
      }
    }
  }
}
```

## CI/CD Integration

Generate specs automatically in CI:

```yaml
# .github/workflows/openapi.yml
name: Generate OpenAPI Spec

on:
  push:
    branches: [main]

jobs:
  generate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3

      - name: Install Rust
        uses: actions-rs/toolchain@v1
        with:
          toolchain: stable

      - name: Generate OpenAPI spec
        run: |
          cargo run --bin generate-openapi

      - name: Upload artifact
        uses: actions/upload-artifact@v3
        with:
          name: openapi-spec
          path: openapi.json
```

```rust

    "My API",
    "2.1.0",  // Semantic versioning
```

### ✅ Document Complex Types

```rust
rpc.query(
    "getUserProfile",
    handler,
    "{ id: number }".to_string(),

      user: {
        id: number;
        name: string;
        email: string;
      };
      stats: {
        posts: number;
```

### ✅ Keep Specs Updated

Regenerate OpenAPI specs when you change your API:

```bash
# Add to your build script
cargo run --bin generate-openapi
git add openapi.json
git commit -m "Update OpenAPI spec"
```

### ✅ Test with Mock Server

Use Prism to test your frontend against the OpenAPI spec:
